📋 Overview

The AWS Operations Agent is an AI-powered tool designed to help DevOps engineers troubleshoot and analyze AWS infrastructure. It provides intelligent querying capabilities across multiple services and can trace requests end-to-end through your infrastructure.

Key Capabilities

Service Capabilities
🛡️ F5 WAF Load balancer configs, origin pools, backend servers, certificates
📍 Route53 DNS Hosted zones, DNS records (A, CNAME, ALIAS), domain resolution
☁️ CloudFront CDN Distribution configs, origins, aliases, caching behaviors
⚖️ ALB/NLB Target groups, health checks, listener rules, routing
📊 Log Analysis VPC Flow Logs, CloudFront access logs via Athena

Step-by-Step Workflow

!

Exception Check: internal.example.com

If FQDN contains internal.example.com, skip F5 check and start with Route53 DNS.

Reason: internal.example.com domains are NOT managed by F5 WAF

1

Check F5 WAF (MANDATORY FIRST STEP)

Call query_f5_load_balancer with the FQDN

If found, MUST call query_f5_origin_pool for each origin pool

Required Output: Origin server type, IP/DNS, port, health check config
2

DNS Resolution (Route53)

Query hosted zones and DNS records

Identify record type (A, CNAME, ALIAS) and target

3

Check CloudFront (if applicable)

If DNS points to *.cloudfront.net, query distribution details

Check origins and cache behaviors

4

Check ALB/NLB (if applicable)

If target is *.elb.amazonaws.com, query load balancer

Get listeners, rules, target groups, and health status

5

Summarize Complete Flow

Present the full infrastructure path from user request to backend targets

🛠️ Available Tools

Primary Tool - AWS CLI (Universal)

⚡ execute_aws_cli_command

The PRIMARY tool for ALL AWS queries. Execute any AWS CLI command dynamically.

PRIMARY Universal

Input Format: 
{"service": "elbv2", "operation": "describe_load_balancers", "parameters": {"Names": ["my-alb"]}}

Supported Services: elbv2, ec2, rds, s3, lambda, dynamodb, route53, ecs, eks, cloudfront, and more

Security: Only read-only operations allowed (describe_*, list_*, get_*)

F5 WAF Tools

⚠️ CRITICAL: F5 tools MUST be called FIRST when tracing any domain (except internal.example.com)

🛡️ query_f5_load_balancer

Query F5 load balancer configuration by FQDN (domain name).

MANDATORY FIRST

Input: fqdn (e.g., "demo.example.com")
Returns: Load balancer details, domains, certificate expiry, origin pools, routes

🔗 query_f5_origin_pool

Query F5 origin pool to get backend server details. MUST be called after query_f5_load_balancer.

MANDATORY

Input: 
{"pool_name": "lb-app-dev-app-svc-443", "namespace": "acme-net"}
Returns: Origin servers (IPs/DNS), port, health check config, load balancing algorithm

📋 query_f5_load_balancer_by_name

Query F5 load balancer by its name (when you know the LB name).

Input: 
{"lb_name": "lb-app-dev-app-svc", "namespace": "acme-net"}

📑 list_f5_load_balancers / list_f5_namespaces

List all F5 load balancers in a namespace or list all available namespaces.

DNS Tools (Route53)

📍 query_route53_records

Query DNS records for an FQDN. Returns hosted zone info and all matching records.

Fallback Prefer execute_aws_cli_command first

Input: fqdn (e.g., "internal.example.com")

🗂️ list_route53_hosted_zones / list_route53_hosted_zone_records

List hosted zones or DNS records with optional filters.

Input: 
{"hosted_zone_id": "/hostedzone/Z123ABC", "name_contains": "api"}

CDN Tools (CloudFront)

☁️ query_cloudfront_distribution

Get CloudFront distribution details by ID or domain name.

Fallback Prefer execute_aws_cli_command first

Input: 
{"domain_name": "demo.example.com"}
or 
{"distribution_id": "E123ABC"}

Load Balancer Tools (ALB/NLB)

⚖️ query_load_balancer

Query ALB/NLB details including target groups and health status.

Input: 
{"dns_name": "my-alb.ap-southeast-1.elb.amazonaws.com"}

📜 describe_load_balancer_listeners

Get ALB/NLB listeners, rules, conditions, and target group IPs.

Returns: Listener ports, routing rules (host/path conditions), target groups with target IPs

Log Analysis Tools

📊 query_vpc_flow_logs

Query VPC Flow Logs from Athena for network traffic analysis.

Input: 
{"source_ip": "10.0.1.100", "destination_ip": "10.0.2.200"}

📈 query_cloudfront_logs

Query CloudFront access logs from Athena.

Input: 
{"distribution_id": "E123ABC", "start_date": "2026-01-20", "end_date": "2026-01-22"}

✅ Best Practices

Tool Selection Strategy

Scenario Recommended Tool
Any AWS service query execute_aws_cli_command (PRIMARY)
F5 WAF / Distributed Cloud query_f5_load_balancer → query_f5_origin_pool
FQDN-based DNS lookup query_route53_records (if AWS CLI insufficient)
Domain-based CloudFront lookup query_cloudfront_distribution (if AWS CLI insufficient)
Network traffic analysis query_vpc_flow_logs

Common Mistakes to Avoid

❌ Don't:
  • Skip F5 check when tracing domains (except internal.example.com)
  • Rely on origin pool info from query_f5_load_balancer alone
  • Mix information from different FQDNs
  • Assume information without calling tools
  • Skip query_f5_origin_pool after finding F5 load balancer
✅ Do:
  • Always start with F5 check for non-internal.example.com domains
  • Always call query_f5_origin_pool for complete backend details
  • Use execute_aws_cli_command as your primary AWS query tool
  • Include origin server details (type, IP/DNS, port) in every F5 response
  • Follow the workflow order: F5 → Route53 → CloudFront → ALB
